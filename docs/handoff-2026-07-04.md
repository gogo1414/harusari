## 0. 선행: DB 마이그레이션 적용 (git보다 먼저)

코드가 `is_savings` 컬럼과 `transactions` UNIQUE 제약에 의존하므로, 배포/실행 전 반드시 아래 두 마이그레이션을 Supabase에 적용해야 합니다.

```bash
supabase db push
# 또는 Supabase 대시보드 SQL Editor에서 아래 두 파일 내용을 순서대로 실행
#   supabase/migrations/20260703_integrity_and_security.sql   # UNIQUE/FK/RLS/중복정리
#   supabase/migrations/20260703_savings_category.sql          # is_savings 컬럼
```

주의: `20260703_integrity_and_security.sql`은 기존 중복 데이터를 정리(삭제/이전)하므로, **운영 DB 적용 전 백업 권장**. 로컬/스테이징에서 먼저 검증하세요.

적용 후 타입 재생성 (기존 `@ts-expect-error` 25건도 함께 줄어듦):

```bash
npx supabase gen types typescript --project-id <PROJECT_ID> > types/database.ts
# 재생성 후 is_savings가 categories에 포함됐는지 확인. (현재는 수동으로 추가해 둔 상태)
```
